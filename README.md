# resid-json

JSON ([RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)) as a format for
[resid-serial](https://github.com/larrydewey/resid-serial), the serialization framework. Any type that
has `Encode`/`Decode` instances — written by hand or generated by
`resid-derive` — goes to JSON and back with these.

```resid
import "src/json.resid";

Int main() {
    Result(Str, SerialError) text = to_json(Point {.x = 1, .y = 2}) else { return 1; };
    println(text);                                  // {"x":1,"y":2}
    Result(Point, SerialError) back = from_json(text) else { return 1; };
    println(f"{back}");                             // Point { x: 1, y: 2 }
    return 0;
}
```

## Entry points

| Call | What it does |
|---|---|
| `to_json(T x) -> Result(Str, SerialError)` | the text |
| `from_json(Str text) -> Result(T, SerialError)` | one value, then `read_end` rejects trailing text |
| `json_encoder()` / `json_decoder(text)` / `json_text(e)` | the raw states, for a caller that threads them itself |

Output is compact: no spaces, no newlines. Whitespace between tokens is
accepted on the way in. The decoder is self-describing, so `Value`,
untagged enums, `flatten`, `tag` and unknown-field skipping all work over
it.

## How the data model maps onto JSON

| Resid | JSON |
|---|---|
| `Bool` | `true` / `false` |
| `Int`, `UInt(64)` | a number, checked against the width on the way back |
| `Int(128)`, `UInt(128)` | a number; a `Value` reads a wider one as its 128-bit form |
| `Float` | its shortest shown text; `NaN` and infinity are rejected when encoding |
| `Str`, `Str(N)` | a string; the two that must be escaped are, the five with short forms are, and other control characters become `\u00XX` |
| `ByteBuf`, `Bytes(N)` | a hex string — JSON has no byte string, so this is the choice, and it round-trips |
| `Unit`, `Option(T)` `None` | `null` |
| `Option(T)` `Some(v)` | `v` |
| `List(T)`, `Set(T)`, `List(T, N)` | an array (a set in sorted order) |
| `Map(K, V)` | an object; JSON keys are strings, so a number or boolean key is written as its text in quotes, and reading it back asks for a `Str` |
| a record | an object, the field names as keys |
| a unit variant | its name as a string |
| a variant with a payload | `{"Name": payload}` |
| `Result(T, E)` | the enum `Result { Ok(T), Err(E) }`, so above |
| `Dec(N)` | its decimal text |

Two shapes are deliberately not recoverable, as in serde: a struct and an
object are one thing on the wire, and so are `Some(v)` and `v`. A `Value`
decoded from JSON keeps what the text said — a map, not a record.

## Tests

```sh
tests/run.sh             # RESIDC=/path/to/residc to pick the compiler
tests/run.sh --update    # rewrite the golden .out files
tests/registry.sh        # the package workflow: upload, then build from a registry
```

207 checks across six programs: the shapes RFC 8259 shows (`vectors`), the
whole model round-tripping (`roundtrip`), the lexical edges — escapes,
surrogate pairs, number forms, whitespace (`text`), what bad text reports
(`errors`), the `Value` tree (`value`), and instances generated by
`resid-derive` (`derive`). `run.sh` builds `resid-derive` from the sibling
checkout and regenerates `tests/model_serial.resid` before compiling.

## Requirements

A Resid compiler with the changes made alongside resid-serial (spec v3.8) —
the same ones resid-serial itself lists. The framework is a dependency in `resid.toml`, and `src/*.resid` import it
by package name (`import "resid-serial/serial.resid";`), so it resolves the
same from a sibling `../resid-serial` checkout or from a registry, and
compiles inside its declared capability ceiling. Build through the
manifest tool (`resid-manifest build resid.toml residc`), or pass
`residc` the dependency map it writes (`resid-manifest depmap resid.toml
deps.txt`, then `residc file.resid -depmap deps.txt`). `./install.sh` in
the Resid checkout installs `resid-manifest` beside `residc`.
